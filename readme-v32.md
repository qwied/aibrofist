# AIBROFIST v32 — Maps Browser и профиль переписаны

## Что было
Обе страницы рисовал вендорный бандл, и они оставались пустыми.
Причина в самом бандле: содержимое показывается только когда
**оба** запроса — `getAvatar` и `getMyName` — успели вернуться:

```js
bn.getAvatar(n, function(e){ Dn.profileImg.src = ...; 2 == ++i && En.onload() }),
bn.getMyName(function(e){ ...; 2 == ++i && En.onload() })
```

Если хоть один колбэк не отработал, счётчик не доходит до двух и
`En.onload()` не вызывается — страница остаётся белой. К этому
добавлялась вторая шапка, вёрстка на `float` и загрузочная заглушка
поверх всего.

Я несколько версий подряд правил это стилями. Так продолжать нельзя,
поэтому обе страницы написаны заново на нашем API.

## Maps Browser
Свои фильтры (режим, автор, сортировка), постраничный вывод, карточки
с названием, рейтингом, автором-ссылкой и датой. Кнопка «Играть»
открывает карту. Автор видит у своей карты «Удалить» — в два касания,
чтобы не снести случайным тапом. На телефоне таблица превращается
в карточки.

Инструменты владельца встают в те же карточки: оценки, режимы,
удаление любой карты.

## Профиль
Поиск игроков, аватарка со скином, дата регистрации, монеты, «о себе»
с редактированием для себя, кнопки дружбы по текущему отношению.
Вкладки: Друзья, Заявки, Отправленные (только у себя), Карты, Скины.
Свои карты удаляются прямо оттуда.

## Заодно
- Вендорные бандлы `users.client.ejs.js` и `mapsBrowser.client.ejs.js`
  удалены — на них больше никто не ссылается, минус ~700 КБ.
- `/getMapsForList` теперь отдаёт число страниц, а не только номер.
- Загрузочная заглушка `.loadingOverlay` спрятана: она могла остаться
  поверх страниц режимов по той же причине.
