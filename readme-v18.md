# AIBROFIST v18 — импорт карт из оригинального brofist.io

## Да, так грузить можно
Файл, который вы прислали, разобрался полностью. Устроен он так:

```
.txt  → список байтов со знаком (Java-стиль, -128..127)
      → поток LZMA-alone: 5D 00 00 80 00 | 8 байт длины | данные
      → JSON сцены
```

В вашем примере: настройки lc=3 lp=0 pb=2, словарь 8 МБ, 1366 байт JSON,
4 тела — точка старта, длинная земля 1000×50 и два блока 100×100 по краям.

Формат сцены:

```json
[{ "x": 1.19, "y": 117.25, "angle": 0, "mass": 0, "id": "spawn",
   "shapes": [{ "x": 0, "y": 0, "width": 30, "height": 100, "angle": 0,
                "radius": 15, "alpha": 0, "id": "spawn", "collision": false,
                "color": "0x000000", "text": "", "make": 3, "type": 1 }] }]
```

Координаты тела — центр в мире, координаты фигуры — смещение внутри тела.
`type`: 1 прямоугольник, 2 круг, 3 треугольник, 4 текст.

## Как пользоваться
В редакторе появилась кнопка **↥ Импорт из brofist.io**. Обычная кнопка
«Открыть» тоже понимает такие файлы — формат определяется сам.

После загрузки показывается отчёт: сколько объектов перенесено,
сколько декораций, сколько не подошло режиму, что срезали по лимитам.

## Что делает конвертер
- **Масштаб 0.73.** Игрок в оригинале 30×100, у нас 22×74. Без пересчёта
  не совпали бы ширина проходов и высота прыжков.
- **Позиции.** Смещение фигуры поворачивается вместе с телом, центр
  переводится в левый верхний угол.
- **Углы.** Определяются автоматически: больше 6.5 бывает только
  у градусов, иначе радианы (Box2D).
- **Типы по имени объекта**: spawn, seeker, finish, checkpoint, coin,
  spike/lava/poison → смертельный, bounce, platform, rotator, gate, door,
  button, lever, cover. Что не опознано — обычный блок.
- **Цвета** `0xRRGGBB` → `#rrggbb`.
- **Наши лимиты соблюдаются**: 2000 объектов, 3 монеты, объекты чужого
  режима отбрасываются с подсчётом.
- **Точка старта.** Если её в файле нет, ставится над верхним объектом.
- Прогон физики на вашей карте: игрок встаёт ровно на землю
  (низ игрока 122.9, верх земли 122.9).

## Новое свойство: «Проходимый»
В оригинале много фигур с `collision: false` — декорации. Раньше они стали
бы стенами. Теперь у объектов есть галочка **«Проходимый (декорация)»**:
такие рисуются полупрозрачными и не мешают движению.

## Распаковщик LZMA
Ни в браузере, ни в Node декодера LZMA нет, поэтому он написан целиком
(`lzma.js`, только распаковка). Сверен с эталоном на 24 наборах: разные
lc/lp/pb и размеры от 0 до 60 КБ — совпало 24 из 24.

## Чего конвертер не знает
Поле `make` в сцене я не расшифровал — в вашем примере всего два значения
(1 у мира, 3 у точки старта). Если в других картах оно означает материал
(лёд, батут), это пройдёт мимо. Пришлите карту с такими объектами —
добавлю. То же с `type: 3` и `4`: они размечены по догадке, живого примера
не было.
